# Редактор «Петрович»

## Состояние

Код редактора находится в `petrovich/` (интерфейс) и `server/admin.mjs` (закрытый API). Публичный сайт собирается из `content/site.json` и шаблонов `index.template.html`, `privacy.template.html` командой `npm run build`. Редактор не связан с калькуляторами и заявками. Цена ТО, акции и ремонтные работы по-прежнему меняются в Google Таблицах.

Адрес панели — **`https://<основной-домен>/petrovich/`**. Ссылок на неё в публичном меню нет. Знание адреса не даёт доступа: данные, предпросмотр, загрузка медиа и публикация требуют серверной сессии. Редактор входит через личный GitHub-аккаунт. ID разрешённых пользователей задаются на сервере: владелец публикует, редактор создаёт черновик и смотрит предпросмотр.

## Что необходимо для включения на домене

1. Выбрать основной домен и разместить Node.js 20+ сервер с постоянным каталогом черновиков. На домене направить **только** `/petrovich/` на этот сервер, а остальной сайт — на статическую публикацию. GitHub Pages не выполняет серверный код и не может самостоятельно обеспечить вход. До этого шага `/petrovich/` на текущем адресе GitHub Pages не будет рабочей панелью.
2. Зарегистрировать GitHub App с callback URL `https://<основной-домен>/petrovich/callback`, включить вход пользователей (OAuth web flow), установить приложение **только** на `sashka1850/service_page`, выдать права `Contents: Read and write` и `Metadata: Read`. Основная ветка должна разрешать приложению публикацию. Ключ и Client Secret держать только на сервере.
3. Заполнить переменные окружения из таблицы ниже. Числовой GitHub user ID владельца указывать отдельно от логина: имя аккаунта может поменяться. ID сотрудников перечислять через запятую. Смену списка доступа применять с перезапуском сервера; проверка роли идёт при каждом запросе.
4. После слияния ветки редактора и развёртывания сервера проверить вход владельца, запрет входа постороннего аккаунта, создание черновика, предпросмотр на телефоне, публикацию и обновление GitHub Pages. Проверить ошибку, если `main` изменился независимо от редактора.

| Переменная | Значение |
|---|---|
| `SCT_ADMIN_ORIGIN` | `https://<основной-домен>` без слеша в конце |
| `SCT_GITHUB_CLIENT_ID` / `SCT_GITHUB_CLIENT_SECRET` | GitHub App OAuth |
| `SCT_GITHUB_APP_ID` / `SCT_GITHUB_INSTALLATION_ID` | ID приложения и установки |
| `SCT_GITHUB_PRIVATE_KEY_FILE` | Путь к закрытому PEM-файлу за пределами репозитория |
| `SCT_OWNER_ID` | Числовой GitHub user ID владельца |
| `SCT_EDITOR_IDS` | Числовые ID редакторов через запятую, можно оставить пустым |
| `SCT_REPOSITORY` | По умолчанию `sashka1850/service_page` |
| `SCT_DRAFT_DIR` | Постоянная директория, по умолчанию `var/editor` |
| `PORT` | Порт Node.js, по умолчанию `8787` |
| `SCT_BIND_HOST` | По умолчанию `127.0.0.1`; менять только при размещении за изолированной сетью контейнеров |

Пример маршрутизации в обратном прокси: `location /petrovich/ { proxy_pass http://127.0.0.1:8787; proxy_set_header Host $host; }`. HTTPS завершается на прокси; при `SCT_ADMIN_ORIGIN=https://…` cookie сессии помечается `Secure`. Не публикуйте `var/editor`, `.env` и закрытый PEM в GitHub или веб-каталоге. Хранилище черновиков должно переживать перезапуск и резервироваться.

Для локальной проверки страницы входа без GitHub App: `npm run admin`, затем `http://localhost:8787/petrovich/`. API корректно отказывает без настроенного входа. Для проверки **всех** действий нужен зарегистрированный GitHub App и разрешённый пользователь.

## Работа с контентом

- Изменения сохраняются в черновик. Сохранение отклоняется, если другой редактор уже сохранил новую версию; перед повтором обновите страницу. Предпросмотр доступен только после входа, не индексируется и показывает текущий черновик.
- Фотографии кадрируются в браузере в два WebP-файла с пропорциями для соответствующего блока и экрана. Сертификаты загружаются целиком без кадрирования (JPG, PNG, WebP до 5 МБ).
- Для первого экрана можно заменить обложку и MP4 до 40 МБ. Видео и изображения пока сохраняются в репозитории GitHub через Git API; при частых заменах крупных видео история будет расти. Для регулярной работы с видео потребуется отдельное файловое хранилище и изменение загрузчика.
- Нажатие «Опубликовать» доступно владельцу. Сервер проверяет схему контента, создаёт новый коммит в `main` с контентом, HTML, JS и медиа. GitHub Pages обновляется своим обычным способом. История Git позволяет откатить публикацию. Если исходники сайта изменились без обновления сервера редактора, публикация блокируется, чтобы не перезаписать новые правки.
- Срок хранения черновиков и порядок резервного копирования каталога `SCT_DRAFT_DIR` задаются при развёртывании. Черновики не содержат заявок клиентов.

## Ограничения текущей реализации

Панель нельзя включить одним коммитом на GitHub Pages: нужен HTTPS-домен, сервер для OAuth и постоянная директория черновиков. Без этих настроек вход и публикация не проходят. Встроенного редактора SEO-метаданных и изменения числа шагов блока 06 нет. Количество шагов зафиксировано на шести из-за его прогрессбара.
