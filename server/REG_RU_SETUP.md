# Заявки на REG.RU, калькулятор в Google

## Что меняется

- Калькулятор и таблицы остаются в Google. Их существующий URL в `src/data.js` сохраняется.
- Форма отправляет имя, телефон и текст обращения на `./api/lead.php` того же домена.
- PHP запрашивает у Google `action=bookingQuote` с идентификаторами услуги, без контактов, текста обращения и ID заявки. Цена и название берутся из таблиц, а не из браузера.
- PHP отправляет сообщение непосредственно через Telegram Bot API. При таймауте статус остаётся неопределённым, автоматической повторной отправки нет.
- В закрытой папке на хостинге сохраняется только техническое состояние: случайный ID заявки, статус, время и HMAC для защиты от дублей и ограничения частоты. Имена, телефоны, тексты заявок и исходные IP в эти файлы не записываются. Срок технического состояния — 30 дней; записи очищаются при следующих запросах. Долговременное хранение заявок и SQL не используются.
- Ограничение: 5 попыток на IP и 15 попыток суммарно за 10 минут. Дубли с тем же ID не расходуют лимит. Лимиты задаются в `api/lead.php`; если используется обратный прокси, нужно отдельно настроить доверенные IP, не доверять произвольному X-Forwarded-For.
- Глобальная файловая блокировка сериализует отправки. При занятом обработчике возвращается SERVER_BUSY; это решение рассчитано на небольшое число заявок.

## Требования

Linux-хостинг с PHP 8.1+ и расширением cURL, действующий HTTPS, исходящие HTTPS-соединения к `script.google.com`, `script.googleusercontent.com` (редирект данных) и `api.telegram.org`. Сверьте доступность этих адресов на выбранном тарифе. Node.js на хостинге не нужен: сборка выполняется до загрузки.

## Порядок включения

1. Подготовьте закрытую папку **вне корня сайта**. Пример структуры: публичная папка `/var/www/USER/data/www/sct-52.ru/`, закрытая `/var/www/USER/data/www/sct-private/`. Не используйте приведённый путь буквально: USER и корень сайта зависят от аккаунта.
2. Скопируйте `server/config.example.php` в закрытую папку как `config.php`. Создайте рядом папку `state`, доступную PHP для записи. Файл конфигурации — права 600, папки — 700, если PHP работает от владельца; проверьте владельца файлов в панели. Не используйте права 777.
3. Заполните token и chat_id текущего бота **только в закрытом файле на хостинге**, origin — точный основной адрес без завершающего слеша (`https://sct-52.ru`), google_api_url — существующий URL Apps Script из `src/data.js`, state_key — случайный секрет минимум 32 символа. Например, получить его можно командой `php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'` в терминале хостинга. Секреты не вставляйте в чат или GitHub.
4. По умолчанию `api/lead.php` ищет `sct-private/config.php` на один каталог выше публичного корня (для endpoint в `корень/api/`). При другом расположении установите серверную переменную `SCT_CONFIG_PATH` с абсолютным путём. Обработчик откажется читать конфигурацию или хранить состояние внутри DOCUMENT_ROOT.
5. Временно остановите приём заявок на время переключения. Обновите `apps-script/Code.gs` в существующем проекте Apps Script и опубликуйте новую версию **существующего deployment**, сохранив URL. В свойствах удалите `ENABLE_LEGACY_LEADS` (или задайте false). Новый `doPost` по умолчанию возвращает LEADS_MOVED. Удалите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` из свойств Google: они там больше не нужны. Не включайте старый путь отправки.
6. Проверьте чтение `?action=version` (версия `2026-11-11.1`), `catalog`, `repairCatalog`, `offers` и `bookingQuote` из Google. Для `bookingQuote` используйте реальные ID услуги из ваших таблиц. Таблицы и их структура не меняются.
7. Локально выполните `npm test`, `npm run build`, PHP-проверки из раздела ниже. Загрузите `index.html`, `privacy.html`, `consent.html`, папки `src`, `assets` и `api` на хостинг. Папки `server`, `tests`, `apps-script`, `.github` и исходные инструкции в публичный корень загружать не требуется. Готовый `src/site.js` уже находится в репозитории.
8. Установите SSL, настройте основной домен и редиректы, затем проверьте заявки. На GitHub Pages PHP не исполняется: новую ветку нельзя включать там как рабочую форму. Откройте приём заявок после проверки REG.RU.

## Проверка на хостинге

- Запрос `GET /api/lead.php?action=status&nonce=booking_00000000000000000000000000000000` возвращает JSON со статусом unknown. SERVER_NOT_CONFIGURED означает ошибку конфигурации; STORAGE_UNAVAILABLE — путь или права папки state.
- Проверьте callback, ТО, ремонт, акцию и свободный запрос автомобиля. После успешной отправки в Telegram должно быть одно сообщение и в форме — подтверждение. В Google не должно уходить имя, телефон или свободный текст: проверьте вкладку Network.
- Повтор POST с тем же ID и теми же данными возвращает прежний статус без второго сообщения. Через 30 дней техническое состояние истекает.
- При недоступном Google платная заявка отклоняется с PRICE_SERVICE_UNAVAILABLE, обратный звонок работает независимо.
- При отсутствии подтверждения Telegram показывает unknown. Кнопка «Проверить статус» обращается к REG.RU и не отправляет повторное сообщение. Если Telegram принял сообщение, но ответ потерялся, автоматического восстановления статуса нет: проверьте чат вручную.
- Убедитесь, что заполненный config.php нельзя открыть через URL и его нет в GitHub. Не включайте логирование тел запросов с контактами или URL Telegram с токеном.

## Автоматические проверки

`npm test` — калькулятор, read-only bookingQuote и запрет старой отправки по умолчанию.

`php -l api/lead.php` и `php -l api/lead-lib.php` — синтаксис.

`php tests/php/lead-test.php` — контакты, согласие, допустимые поля Google, проверка цены.

`python3 tests/php/endpoint-test.py` — настоящий локальный PHP HTTP endpoint с подменой внешнего cURL: доставка, дубли, статус, лимит, отказ Telegram и неопределённый сетевой результат. Никаких настоящих сообщений не отправляет. Требуется PHP CLI с поддержкой встроенного сервера и свободный localhost-порт. Эти проверки также запускаются в GitHub Actions.

## Границы изменения

Перенос меняет технический маршрут заявок. Передача имени/телефона в Telegram сохраняется; это изменение само по себе не подтверждает выполнение требований законодательства о персональных данных. Политика остаётся прежней. Отдельная страница `consent.html` содержит утверждённый текст согласия без названия мессенджера.


## Согласие

Галочка по умолчанию пустая, ссылка ведёт на `consent.html`; политика доступна отдельной ссылкой. Версия согласия `2026-11-11.1` проверяется PHP, устаревшая версия отклоняется с CONSENT_OUTDATED. При изменении текста сохраняйте предыдущую редакцию в истории Git и одновременно обновляйте версию в странице, `src/data.js`, PHP и тестах.

PHP фиксирует серверную дату UTC и версию согласия в закрытом `lead-state.json`, связанные с ID заявки и HMAC её данных. Контакты в файл не записываются. Версия и дата также включаются в сообщение сотрудникам. Техническое состояние хранится до 30 дней и удаляется при следующем обращении к обработчику после истечения срока; при отсутствии трафика настройте ежедневную очистку через планировщик хостинга.

Утверждённый текст ограничивает обработку завершением обращения, максимум 30 днями, либо отзывом. Сотрудники должны выполнять прекращение обработки и удаление заявок, включая сообщения в рабочем чате и их копии, с учётом законных оснований и сроков. Автоматическое удаление сообщений эта реализация не выполняет. Отсутствие SQL-базы не отменяет эту процедуру.
